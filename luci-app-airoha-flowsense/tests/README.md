## Save / Apply / Reset contract

Only the Settings route has the native footer. Save atomically stores fixed, validated fields in root-private `/etc/flowsense/pending.json` (directory 0700, file 0600), without UCI commit or service/sysctl changes. Page reload retrieves this pending baseline; Reset discards only unsaved browser edits, matching LuCI Reset semantics. Pending data is not runtime telemetry. `getSettings` also returns the committed-only `monitor` read by the existing monitor getter, independently of pending read success/errors. Settings uses this field for initial values and Apply readback instead of requesting `getOverview`: initial load is two RPCs, and a complete Save & Apply is five RPCs. It does not collect uptime, jitter or interfaces; Status and its poll cadence are unchanged. `test_settings_rpc.js` asserts these counts and the native Save/Reset/reload, Apply/partial retry, unknown/readonly and pending-error paths; real-UCI settings tests prove committed/staged/override isolation, fresh reads and no telemetry collection. The shared runner executes `test_view.js` in both normal and Chinese error modes.

Apply saves current edits first, binds its request to those verified fields using the optional `expected` JSON string, invokes the original acceleration and monitor transactions, then reads both groups back. The backend compares the expected fields with pending settings under its operation lock and rejects a different session's intervening Save without applying it. Legacy callers omitting `expected` retain their previous behavior. The native Apply readback paints once; a failed pending readback still updates independently observed runtime and reports a refresh warning after a confirmed transaction. A successful group is removed from pending; a failed group remains retryable. The response distinguishes groups and returns underlying failure codes, including rollback failure. It never invokes global LuCI UCI apply. The public legacy monitor setter shares the Settings transaction lock through restart, readback and rollback; staged Apply calls the already-locked inner transaction without reacquiring it. Settings operations serialize with a runtime lock; a reboot cannot preserve a stale lock. As with existing setters, external concurrent config writers are not coordinated by this package lock. State-changing API requests still require write ACL.

`applySettings` is the confirmed transaction boundary. Independent `getSettings`/`getAcceleration` failures afterwards produce an applied-but-refresh-failed warning, not a transaction error. The notification's **Refresh current state** action only reads, including with write permission revoked; it does not Save or Apply. Unknown monitor values are cleared/indeterminate, not inferred from the request. Confirmed groups are removed from the local baseline even when refresh/checkpoint reads fail; only an exact matching stale group is suppressed on later refresh, so another session's different pending request is preserved. A new Save clears the old completion mask only after every pending field has been read back and verified, preserving a newly saved request even when its values match the previous Apply. Actual partial failure and checkpoint-storage warnings retain their separate meanings. `test_refresh_recovery.js`, `test_checkpoint.js` and the real-UCI Python integration cover transport/storage/invalid pending reads, acceleration failure, partial completion, recovery without replay and a new Save following an intervening committed change in another session. Chinese mode now compiles the catalog using prebuilt `PO2LMO` and verifies native LuCI lookups; set `PO2LMO` if it is not at LuCI's default path.

Acceleration preparation checks every `want/new/old` printf/redirection before arming rollback or entering live mutation. The real ash/UCI regression injects open failures and real `/dev/full` printf failures (including a partial ordinary-file prefix) at all 19 preparation writes; all 57 cases require `prepare`, unchanged configuration/runtime bytes and mtimes, no firewall restart, no live mutation and complete scratch cleanup.
